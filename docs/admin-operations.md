# Secure supervision operations
New native SPA workflows: company transitions (pending -> verified/rejected, rejected -> pending, verified -> suspended, suspended -> verified), traveler disable/enable, support status and reply, paginated internal audit. All new endpoints require a valid MFA session even in development. GET/POST only on detail endpoints; CSRF on mutations; strict JSON fields, explicit confirmation and reason, stale status/version checks, row locks and transactional audit. No privileged-user editing or account deletion. Company suspension and traveler deactivation are refused while future active held/test-paid bookings exist; resolve these first. This conservative policy avoids stranding travelers, but an emergency fraud/security procedure is still needed before launch. Traveler session_version invalidates old session hashes even after reactivation, without changing the password; push subscriptions removed. Existing sessions with version zero retain the standard Django hash. Reserve checks active/version again under the existing user lock. No claim of revoking already in-flight operations. Audit covers these new workflows, not every existing financial or MFA event; no update/delete API for this journal, not an external tamper-proof log. Support replies overwrite the current reply; no chat thread in this increment. Native /admin/ remains blocked in production. New interface labels initially French. Run migrations, targeted tests, full suite, and real browser MFA workflows before merge. No payment provider changes.
