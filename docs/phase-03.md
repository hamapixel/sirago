# Phase 03 — Gestion des compagnies (premier lot)
Les propriétaires de compagnie peuvent enregistrer des cars, trajets et départs (brouillons), modifier leurs données et publier uniquement après validation BTDIGIT. Les compagnies suspendues ou rejetées sont en lecture seule. Les départs récurrents sont générés sur 31 jours maximum, avec choix des jours. Les écritures sont sérialisées par verrou PostgreSQL sur la compagnie ; les chevauchements de cars sont refusés dans les opérations API. Les tarifs sont des entiers XOF. Les trajets et cars ne sont pas supprimés ; les modifications incompatibles avec un départ futur sont refusées. Les départs publiés ne sont pas directement modifiables : suspendre/annuler selon les règles de cette phase. Les réservations n'existent pas encore : avant leur ajout, les transitions de départ doivent devenir compatibles avec les réservations, remboursements et notifications. L'écran indique les capacités proposées et non les places réellement restantes. La liste de villes reste limitée aux neuf villes du socle. La liste publique et la recherche réelle sont réservées à la phase 04, les employés, les ventes et les contrôles à des phases suivantes. Pas de changement d'architecture.
Tests : migrate, check, test, makemigrations --check --dry-run, npm test, npm run build. Vérifier manuellement l'interface mobile, les droits de deux compagnies, le chevauchement, la récurrence et la publication.
